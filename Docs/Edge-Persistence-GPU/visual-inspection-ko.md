# GPU 원본 프레임 직접 검사

이번 비교의 두 번째 열은 CPU 예상 영상이 아니라 새 GPU 구현의 실제 출력이다.
검사 입력은 `bistro-quality.json`, `minecraft-quality.json`, 프레임/ROI/배율과
미디어 경로는 `media.json`에 기록했다. GIF는 10 fps, 원래 60 fps의 1/6 속도다.
팔레트 양자화가 있으므로 수치·미세 색상 판단에는 원본 PNG와 무손실 WebP를 쓴다.
GIF는 시퀀스 전체를 한 번에 양자화한 공통 팔레트와 dithering Off를 사용한다.
프레임마다 다른 팔레트 때문에 추가 깜빡임이 생기는 것을 피하기 위한 출력 설정이다.

## 직접 연 이미지

- Bistro/Minecraft 각각 f131의 기존 ⑥, 새 GPU 구현, 원본 ④, 고해상도 참조 PNG.
- Minecraft thin-line: ROI (956,524,1020,620), nearest 3배.
- Bistro chairs: ROI (1230,582,1358,670), nearest 2배.
- Bistro window: ROI (906,470,1034,558), nearest 2배.
- 세 ROI 모두 이동 f130~135, 이동→정지 f178~183, 정지 f190~195의 6연속 프레임.
- Minecraft 문제 구간은 뒤쪽 f136~141까지 확장해서 추가로 직접 확인했다.
- 밝기/색상 보정과 차이 증폭 없이 원본 RGB를 확인했다. 정지 프레임 검사와
  GIF 파일 제공/디코드 검증을 구분하며, 재생 영상을 직접 관찰했다고 주장하지 않는다.

## 관찰

### Minecraft 얇은 수직선

기존 ⑥의 f131/f134에서 끊겨 보이던 위쪽 선 구간이 새 구현에서는 다시 나타난다.
f131 (971,544)의 RGB는 기존 (163,162,150)에서 새 (142,140,131),
f134 (972,544)는 (163,163,150)에서 (141,140,130)으로 바뀌었다.
이 위치들은 현재 edge가 아니었지만 재투영한 직전 raw edge로 추가 선택된 위치다.

다만 이것으로 선 소실·단절이 전부 해결되지는 않았다. f132 (972,544),
f135 (973,544)는 이미 현재 edge로 선택돼 있던 위치여서 각각
(140,138,128), (138,137,127)로 기존 출력과 동일하다. 연속 프레임에서 선의
농도와 연결 상태가 달라지는 문제가 남아 있다. 원본 T2X-R과 같은 구조 보존
품질에 도달했다고 판정하지 않는다.

추가로 연 f136~141에서도 기존 선의 출현/소멸이 모두 제거되지는 않았다. 특히
f137에서는 새 구현에도 중간 구간의 단절이 남는다. 원본 ④ 역시 모든 프레임에서
고해상도 참조와 같은 선을 유지하는 완전한 정답은 아니다.

정지 전환에서는 f181부터 추가 후보가 0이 되고, f190~195의 새 출력은 기존 ⑥과
동일하다. 표본이 없는 정지 상태의 얇은 구조를 새로 복원하는 기법은 아니다.
원본 ④의 지터 On 패턴과 비교할 때 남는 정지 공간 품질 차이도 그대로다.

### Bistro 의자와 창문

의자 다리·바닥 경계와 창문 격자 주변의 일부 픽셀이 바뀌지만, 기존 ⑥과 새 구현의
차이는 Minecraft의 해당 선 복원 사례보다 작다. f130~135의 가는 다리/격자
구조와 경계의 불규칙함을 전면 해결했다고 보기 어렵다. 정지 구간에서는 기존과
새 구현이 같아 차이가 없다. 두 ROI의 평균 오차나 변화량 감소만으로 체감 품질
전반의 향상을 판정하지 않는다.

## 정량 수치와 해석의 한계

이동 구간의 전체 화면 RGB MAE는 Bistro에서 0.682871→0.678393으로 줄었지만,
Minecraft에서는 1.599557→1.631267로 늘었다. Minecraft는 동시에 PSNR이
35.044742→35.280978 dB로 높아져 지표끼리도 방향이 다르다. 일부 큰 오차의 감소와
다수 작은 오차의 증가를 평균 하나로 품질 우열로 단정할 수 없다.

이동 중 reference-delta residual은 두 장면에서 줄었지만 카메라 이동과 공간 참조의
한계를 포함하는 보조값이다. 절대 깜빡임/고스팅 점수로 표현하지 않는다. 원본 ④가
이동 중 일부 평균 지표에서 불리하더라도 얇은 선의 시각적 안정성을 무시하지 않는다.
이번 GPU 구현에 CGVQM을 새로 실행하지 않았으며 과거 CPU 예상 점수를 재사용하지 않았다.

현재/직전 edge 합집합에는 이전 depth·표면 식별 기반 가려짐 해제 거부가 없다.
따라서 이번 선 복원 사례를 global ghosting 해결 또는 움직이는 물체까지의 효과로
일반화하지 않는다. 구현 정확성 통과와 최종 품질 목표 달성은 별개다.
