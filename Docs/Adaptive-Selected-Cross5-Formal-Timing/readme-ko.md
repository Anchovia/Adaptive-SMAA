# 최종 조합 정식 시간 측정 (전체 화면 1920×1080)

브랜치 `validation/adaptive-selected-cross5-formal-timing`은 정리 브랜치 `tooling/adaptive-selected-cross5-minimal`의 `60bae94`에서 분기했다. 지금까지의 시간은 모두 숨김 창에서 잰 engineering 값이었다. 보고서에 쓸 정식(formal) 값을 얻으려고 정리 브랜치의 실행 파일 구성으로 다섯 mode를 화면에 띄운 상태에서 쟀다. 사용자가 화면 조건을 전체 화면 1920×1080으로 정했다. 2026-11-21에 쟀고 push하지 않았다. 렌더러와 셰이더는 바꾸지 않았다(SMAA 폴더는 `60bae94`와 같다). `-R`은 계속 camera/depth reprojection만 뜻한다.

## 화면 조건을 정한 과정

처음에는 창 모드로 화면에 띄우려 했다. 실행 전에 같은 조건으로 Bistro Smoke를 두 번 시험 실행했고 둘 다 정식에서 뺐다.

| 시험 실행 | 보고서 | 조건 | 결과 |
|---|---|---|---|
| `aft-probe` | `20261121_005751` | 창 모드, 클라이언트 1920×1061, 위치는 앱이 정함 | 창이 (130,130)–(2066,1230)에 놓여 오른쪽과 아래가 화면(1920×1080) 밖으로 나갔다. 실행 중 사용자 입력이 있었다(사용자가 이때 화면을 캡처했다). |
| `aft-probe2` | `20261121_005935` | 창 모드, 클라이언트 1904×1001, 위치 (0,0) | 창이 작업 영역 (0,0)–(1920,1040)에 정확히 들어갔고 입력과 창 변화가 없었다. |

1920×1061 클라이언트는 창 테두리를 더하면 1936×1100이라 이 화면(1920×1080, 작업 표시줄 40 px)에 다 들어가지 않는다. 사용자는 창 대신 전체 화면 1920×1080을 골랐다.

전체 화면은 borderless(3)로 했다. 이 데모의 전체 화면은 2와 3 모두 창 테두리를 없애고 창을 모니터 크기로 키우는 방식이다(`vaApplicationWin::SetFullscreenWindowInternal`). 2는 여기에 DXGI exclusive 모드를 더 요청하는데, 코드 주석대로 상황에 따라 borderless나 창으로 내려갈 수 있고 포커스를 잃으면 풀릴 수 있다. 3은 화면 모드를 바꾸지 않는다. 네 실행 모두 보고서에 `Resolution: 1920 x 1080`, `Fullscreen: Fullscreen Borderless`, `Vsync: OFF`가 찍혔고, 창은 실행 내내 (0,0)–(1920,1080)에서 바뀌지 않았다. 멈춤이나 창 모드로 돌아간 일은 없었다.

## 실행

조건은 숨김 창 측정과 같다. Release x64, DirectX 11, Ultra, VSync Off, 측정 중 앱 내부 UI 숨김. 장면마다 Smoke 다음 Benchmark를 독립 clean process로 돌렸다. Benchmark는 30초 대기와 warm-up 300프레임 뒤 4,800프레임씩 6회 재며 반복마다 mode 순서를 정방향과 역방향으로 바꾼다. RTX 3060 Ti, 드라이버 621.14다. 실행 파일 SHA-256은 `C78D9E52…A14241`, git head는 `115eb8d`이고 렌더러 소스 변경은 없었다. 결과 분류는 formal(창 visible, 전체 화면)이다.

실행 전마다 CMAA2 0개, GPU P8(사용률 0~2%), 게임이나 영상 프로그램 없음, 60초 이상 키보드·마우스 입력 없음을 확인했다. 실행 중에는 1초마다 CMAA2 창의 위치, 크기, 최소화·최대화 상태를 기록했다. 네 실행 모두 실행 중 입력과 창 변화가 없어 다시 잰 것은 없다. 보고서에 `failed_size`, `failed_window_state` 행도 없었다. 끝난 뒤 남은 CMAA2는 0개였다.

정리 브랜치의 Cross5 resolve는 결합 브랜치와 셰이더 바이트가 다르다(같은 출력). 그래서 시간이 같은지가 가정이었다. Cross5가 늘린 resolve 시간은 정식에서 Bistro +1.92 µs(Original과 Adaptive 모두), Minecraft +6.76 / +6.77 µs였고, 결합 브랜치 숨김 측정은 +2.06 / +1.98 µs, +7.35 / +7.47 µs였다. Cross5를 켠 resolve 시간 자체는 정식 Bistro 10.14 / 10.20 µs, Minecraft 35.46 / 35.57 µs이고 숨김 측정은 10.22 / 10.19 µs, 35.91 / 36.00 µs다. 해상도가 1.8% 큰데도 정식 값이 같거나 조금 작아, 다시 쓴 셰이더가 더 느려졌다는 근거는 없었다. 두 값은 다른 프로세스와 해상도에서 나왔으므로 같은 시간이라고 단정하지는 않는다.

숨김 측정의 Bistro에서 Adaptive mode의 카메라 velocity가 0.4 µs 늘었던 것은 이번에는 나타나지 않았다(+0.05 [−0.07, +0.17] µs).

## 정리

- 최종 조합 A+선택 경로+Cross5의 AA 시간은 전체 화면 1920×1080 정식 측정에서 ④ 대비 Bistro −23.27%, Minecraft −3.41%였다.
- 같은 경로 Original(선택 경로+Cross5) 대비 Adaptive 효과는 −6.69% / −4.52%, Cross5 없는 A+선택 경로 대비 Cross5 비용은 +1.61% / +3.17%였다.
- 결합 브랜치의 숨김 창 측정과 여덟 비교 모두 방향이 같았고 크기 차이는 최대 0.63%p였다.
- 전체 GPU 프레임은 ④ 대비 Bistro −1.11%, Minecraft −0.30% [−0.61, +0.01]이고, 실제 프레임 간격(WallFrame)은 −0.10% [−0.26, +0.06], −0.19%였다. AA 패스의 차이가 프레임 전체에서는 1% 안팎이다.
- 정리 브랜치의 다시 쓴 Cross5 resolve가 결합 브랜치보다 느려졌다는 근거는 없었다(Cross5가 늘린 resolve 시간 정식 1.92 / 6.77 µs, 숨김 1.98 / 7.47 µs).
