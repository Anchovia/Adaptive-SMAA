# Adaptive SMAA와 두 기준선의 결합 (20번, 21번)

브랜치 `experiment/adaptive-selected-temporal`은 `baseline/selected-temporal`(b6c3ebc)에서 분기했다. 기존 Adaptive SMAA 공간 탐색을 독립 스위치로 붙이고 다음 세 구성을 더했다. `-R`은 계속 camera/depth reprojection만 뜻한다.

| 번호 | 구성 | 하니스 모드 이름 |
|---|---|---|
| A-④ | Adaptive SMAA + 원본 T2X-R | `A-T2X-R` |
| 20번 | Adaptive SMAA + 선택 경로 | `A-` + 선택 경로 이름 |
| 21번 | Adaptive SMAA + 19번 | `A-` + 19번 이름 |

④, 선택 경로, 19번은 같은 실행 파일에서 그대로 돌아간다. 하니스는 여섯 모드를 같은 프로세스에서 번갈아 실행한다.

## 구현

Adaptive 코드는 `research/tscmaa-inspired-smaa-core`의 Adaptive 공간 처리에서 가져왔다. edge 패스가 R8 대비 단계(finalDelta 0.1 미만 0, 1/3 미만 0.5, 그 이상 1)를 따로 쓰고, weights 패스가 이 값을 읽어 직교 탐색을 4/8/최대, 대각 탐색을 3/절반/최대로 줄인다. 모든 변경은 `SMAA_ADAPTIVE_SEARCH` 매크로 안에 있다.

- `SMAA.cpp`: 생성자 인자 `adaptiveSearch`로 매크로를 넣고 R8 metaRT를 만든다. edge 패스 출력은 edge, (Adaptive면) meta, (19번이면) velocity 순서로 묶는다.
- `SMAAWrapper.hlsl`, `SelectedTemporal.hlsl`: edge 패스가 `SMAA_EDGE_OUTPUT`을 돌려준다. Adaptive가 꺼져 있으면 이 타입은 기존 `float2`와 같다. 19번의 velocity 출력 슬롯은 Adaptive에서 SV_TARGET2로 밀린다.
- `vaSMAAWrapper::ApplyTemporalRoute(route, adaptiveSearch)`로 여섯 구성을 고른다. 값이 바뀌면 SMAA 객체를 다시 만든다.

Adaptive에서는 edge 텍스처가 원래 Adaptive 구현처럼 RG8이다. Original은 NVIDIA에서 RGBA8을 쓴다. 이 형식 차이가 Adaptive 결합 효과와 섞여 있어서 아래 시간 차이를 탐색 범위 축소만의 효과라고 말할 수 없다.

## 코드 변화량

기준은 `baseline/original-smaa`(ee0020d)의 `Projects/CMAA2/SMAA` 폴더이고 `.cpp .h .inl .hlsl .hlsli`만 센다. 공백과 빈 줄 변경은 세지 않았다. 코드 줄은 추가 줄에서 빈 줄, `//` 주석, 블록 주석을 뺀 값이다. 이번에 블록 주석까지 빼는 규칙으로 모든 행을 다시 셌고, 그 결과 Adaptive 행만 이전 표의 145에서 134로 바뀌었다.

| 구성 | 추가 | 삭제 | 추가 중 코드 줄 |
|---|---:|---:|---:|
| Adaptive SMAA (`main`) | 181 | 56 | 134 |
| ④ `baseline/smaa-t2x` | 226 | 43 | 194 |
| 기준선 (④ + 선택 경로 + 19번) | 545 | 61 | 441 |
| 이 브랜치 (기준선 + Adaptive) | 690 | 97 | 579 |

기준선 대비 이 브랜치의 추가분은 +158/-49, 코드 151줄이다. 그중 `SMAA.hlsl`이 +83/-22로 가장 크고, Adaptive를 선택 경로와 19번에 연결하는 데 쓴 부분(`SMAA.cpp`, 두 wrapper, `SelectedTemporal.hlsl`, `vaSMAAWrapper*`)은 +75/-27이다. `main`의 Adaptive는 `SMAA.fx`도 +9/-7 고쳤지만 이 브랜치는 DX11 경로만 쓰므로 `.fx`를 건드리지 않았다.

## Original 경로 회귀

Adaptive를 끈 세 모드는 기준선과 출력이 같아야 한다. FXC로 Original 셰이더 바이트코드가 기준선과 같음을 먼저 확인했다. 이어서 같은 하니스로 두 장면을 240프레임씩 캡처해 기준선 브랜치의 캡처와 복호화 RGB를 비교했다. ④, 선택 경로, 19번 모두 불일치 0프레임이다(`original-vs-baseline.json`).

20번과 21번의 차이 분포는 거의 같다. 19번과 선택 경로 사이의 작은 RGB 차이는 Adaptive에서도 그대로 남는다.

원본 PNG를 nearest 확대로 직접 열어 확인했다. 시트는 `D:/SMAAResearchCaptures/c20-adaptive-20261107/inspection/`에 있다.

- Bistro 의자 ROI(1230,582–1358,670), f126–f131, 2배: 차이는 의자와 탁자 경계에 흩어진 점이고 최대 5–12다. 의자 다리와 가로대는 두 결과에서 같은 위치에 끊김 없이 보인다.
- Minecraft 이음매 ROI(956,524–1020,620), f126–f131, 3배: 차이는 세로 이음매를 따라 최대 8–16이다. 이음매의 연속성은 두 결과가 같다. f128과 f130에서 이음매가 약해지는 현상은 선택 경로와 20번 모두에 있다. 이것은 기준선에 이미 있던 문제이고 Adaptive가 만든 것은 아니다.
- 최대 차이 위치: Bistro (1031,487)은 창틀 경계의 두 점이 이동 끝(f180)부터 차이가 커져 정지 구간 내내 118로 남는다. history 누적이 차이를 유지하는 것으로 보인다. Minecraft (1669,962)는 풀 블록 경계의 한 점이 f160에 147로 튀었다가 98, 57, 37로 줄어든다. 두 곳 모두 고립된 한두 픽셀이고 선이 사라지거나 끊기는 곳은 찾지 못했다.

이 검사는 Original과 Adaptive가 서로 얼마나 다른지만 본다. 기준 영상과의 비교는 다음 절에 있다.

## 기준 영상과의 품질 비교

1~17번 재측정에 쓴 supersample 기준 영상은 10월 15일 미디어 정리 때 지워졌다. 그래서 하니스에 `-smaaColorBlendOptimizationReferenceCapture`를 추가해 같은 240프레임 경로에서 다시 찍었다(febfa57, 렌더러 코드 변경 없음). 설정은 9월 기준 영상과 같다. 2배 해상도, 3×3 격자, 8×MSAA이고 history는 쓰지 않는다. 같은 프레임의 공간 기준이므로 temporal 정답 영상은 아니다.

새 기준 영상이 예전 것과 같은지 먼저 확인했다. ④와 선택 경로(⑰과 240프레임 RGB가 같다)의 PSNR, SSIM, RGB MAE를 두 장면 세 구간에서 다시 계산했고, 2026-10-07 재측정 값과의 상대 차이는 최대 6×10⁻⁸이었다(`reference-bridge.json`). 계산식과 구간도 그때와 같다. 이동은 f60–179, 정지 전환은 f180–209, 정지는 f220–239다(`c20_quality.py`, 결과 `quality.json`).

## 시간 측정

2026-11-07, RTX 3060 Ti, 1920×1061 숨김 창, 드라이버 610.88. 실행 파일은 위 RGB 캡처와 같다(495AFA16…). 측정 전 GPU 부하를 만들던 다른 프로그램을 끄고 재부팅했고, 각 실행 시작 시 GPU는 P8, 사용률 0–6%였다. 장면마다 독립 프로세스 하나에서 여섯 모드를 번갈아 돌렸고, 300 warm-up 뒤 4,800프레임씩 6회 반복했다. validation은 모두 PASS다. 변화율은 같은 실행의 반복마다 짝지어 계산한 뒤 평균했고, 괄호는 그 95% 구간이다(다중 비교 보정 없음). 계산은 `c20_time.py`, 원시 수치는 `performance.json`에 있다.

전체 프레임 시간에서 Adaptive만의 변화는 -0.29~-0.53%로 작다. 이 중 Bistro 세 쌍과 Minecraft 21번−19번은 구간이 0을 포함하므로 차이가 있다고 말할 수 없다.

## 한계

- RTX 3060 Ti 한 대, 1920×1061 숨김 창에서만 확인했다. 숨김 창 측정이므로 논문용 FPS 수치로 쓰지 않는다.
- 단계별 Profile(edge, weights, neighborhood 각각)은 재지 않았다. Adaptive가 weights 패스를 줄였는지 edge 패스의 meta 출력이 얼마를 더했는지는 나누지 못했다.
- Adaptive 효과와 edge 형식(RG8/RGBA8) 차이가 섞여 있다.
- 품질 비교는 supersample 공간 기준 영상과의 PSNR/SSIM/MAE와 원본 프레임 직접 검사까지다. CGVQM은 계산하지 않았고, 기준 영상은 temporal 정답이 아니다.
- 6모드 캡처(실행 파일 495AFA16…)와 기준 영상 캡처(42841978…)는 실행 파일이 다르다. 둘 사이에는 하니스 변경만 있고 카메라 경로 코드는 같다. 정렬은 ④와 선택 경로 수치가 9월 기준 영상 결과와 일치하는 것으로 확인했다.
- reprojection Off 변형(`O-ET2X`/`A-ET2X`에 해당하는 선택 경로)은 아직 없다.
