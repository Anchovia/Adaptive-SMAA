# 미래설계학점 2주차 활동 정리

**연구 주제:** 실시간 렌더링 환경에서의 안티앨리어싱 성능 최적화 기법 연구

**활동 주제:** 확보한 TSCMAA 소스 코드의 처리 구조 및 핵심 알고리즘 분석

**정리일:** 2026-09-14

## 1. 활동 목표

본 연구는 논문 작성을 목표로 SMAA의 품질과 실행 비용을 개선하는 연구다. 공간 처리에서는 luma 대비에 따라 탐색 범위를 조절하는 Adaptive SMAA를 구현하고 일정 수준의 효과를 확인했다. 이후 temporal 처리에서도 개선 가능성을 찾기 위해 Intel TSCMAA의 선택적 누적 방식에 착안했다.

이전에는 원본 코드를 확보하지 못해 공개 발표 자료와 문서에 근거한 SMAA adaptation을 구현했다. 이번에는 교수님을 통해 확보한 TSCMAA 소스의 실제 계산과 실행 구조를 분석하여, 문서로 추정했던 부분을 코드 근거로 구체화하는 것을 목표로 했다.

## 2. 분석한 내용과 과정

### 기존 분석·검사 기록 검토

먼저 2026-09-10에 작성된 소스 분석, shader bytecode 비교, 후보 함수 및 history 필터·clipping 검사 기록을 검토했다. 이 기록은 이번에 새로 수행한 GPU 실험과 구분했다.

현재 AASample 폴더와 이전 분석 대상의 동일성을 확인하기 위해 기록된 텍스트 파일 25개를 SHA-256으로 대조했고 모두 일치했다. 현재 동봉 shader header 12개의 바이트 배열도 이전에 보존된 컴파일 결과 및 동봉 bytecode와 일치했다. 이번 작업에서는 셰이더 재컴파일이나 GPU 검사를 다시 실행하지 않았다.

### 전체 처리 구조 연결

애플리케이션이 전달하는 color, depth, 카메라 행렬부터 최종 출력까지 C++ 호출과 HLSL 함수를 연결했다. 에지 검출 단계에서 공간 처리용 후보와 temporal 처리용 후보가 함께 만들어지고, CMAA 공간 처리 이후 temporal 후보에만 history 결합을 수행하는 구조를 확인했다.

특히 color 입력과 공간 처리 출력이 같은 texture의 서로 다른 view로 연결되어 있음을 확인했다. 같은 변수라도 실행 시점에 따라 내용이 바뀌므로, temporal clipping이 실제로 읽는 영상은 CMAA 공간 처리를 마친 현재 프레임이라는 점을 구분했다.

### 핵심 알고리즘 분석

후보 선별에서는 가중 RGB 차이의 최댓값, threshold subtraction, 연결된 수직 에지 응답의 평균을 이용한 억제, 추가 threshold 적용 순서를 정리했다. 후보를 선택하는 계산과 선택된 좌표를 목록에 모아 indirect dispatch로 실행하는 과정을 구분했다.

Temporal 처리에서는 depth와 카메라 행렬을 이용한 reprojection, 5-tap history sampling, YCoCg 통계 기반 clipping, 현재 색과 history의 결합, 다음 프레임으로의 feedback을 분석했다. 공개 문서와의 대응은 기술 문서의 비교표로 정리했다.

### 이번에 추가로 확인한 연결·초기화 문제

셰이더 변수 이름과 C++에서 전달하는 실제 값이 항상 같은 의미는 아니었다. `prevProj`에는 현재 projection이 전달되며, 첫 두 호출의 View 저장 순서에도 확인이 필요한 문제가 있었다. History texture는 처음에 흰색으로 초기화되고, 첫 프레임을 현재 영상으로 seed하는 별도 분기는 없었다.

또한 일반 Desktop 표시 경로는 라이브러리가 반환한 temporal 결과 대신 CMAA 공간 결과를 읽는 반면, VR 제출 경로는 반환된 temporal 결과를 사용했다. Resize 시에는 렌더 대상 재생성과 TSCMAA 입력 view·history 상태의 갱신을 함께 확인해야 함을 파악했다. 이 항목들은 소스 분석 결과이며, 실제 화면이나 동봉 실행파일에서 재현한 결과는 아니다.

## 3. 새롭게 이해한 처리 원리

TSCMAA의 선택적 temporal 처리는 단순히 화면의 일부를 골라 이전 프레임과 섞는 한 단계가 아니다. 후보를 판단하는 에지 응답, 목록 저장, 공간 처리 완료 시점, history 좌표, sampling과 clipping의 색 공간, 최종 history 저장이 함께 연결되어 있다.

특히 다음 사항을 구체적으로 이해했다.

- 공간 처리 후보와 temporal 후보는 같은 에지 검출에서 만들어지지만 서로 다른 선별 조건을 사용한다. 두 목록을 동일한 후보 집합으로 취급할 수 없다.
- 공개 설명의 후보 비율과 실제 목록의 메모리 용량은 서로 다른 개념이다. 코드에서 화면의 절반을 반드시 선택하는 규칙은 확인되지 않았다.
- 확보 소스의 clipping은 YCoCg에서 통계를 계산한 뒤 RGB에서 clamp한다. 명칭이 같더라도 기존 SMAA adaptation의 연산과 같지 않다.
- History feedback은 최종 temporal 결과를 다음 프레임에 다시 사용하는 구조다. 초기화와 행렬 저장이 올바르게 맞물려야 한다.
- 라이브러리의 출력과 화면에 표시되는 texture가 같은지 확인해야 하며, 함수 이름이나 UI의 모드 이름만으로 판단해서는 안 된다.

## 4. 검증 결과와 한계

이번 활동에서는 전체 소스 흐름과 핵심 수식을 정리하고, 이전 검사 대상과 현재 소스의 동일성을 확인했다. 기존 GPU 검사에서 확인된 부분 함수의 결과와 이번 정적 분석에서 찾은 문제를 구분한 검증표도 작성했다.

다만 전체 후보 mask, shared-memory 경계, first-frame·resize 동작, 최종 출력의 정확성은 GPU에서 추가 검증해야 한다. 동봉 EXE/LIB가 현재 소스와 대응하는지도 아직 확인하지 않았다. 따라서 이번 결과를 TSCMAA 전체 구현 검증 완료나 실제 화질·성능 개선으로 표현하지 않는다.

기존 문서 기반 SMAA 구현과 확보 소스 사이에 차이가 존재한다는 사실은 확인했지만, 그 차이가 이전 수치 부진의 원인이라는 인과관계는 아직 검증하지 않았다. 기존 Adaptive SMAA 및 temporal 연구 결과는 각 구현의 결과로 보존한다.

## 5. 다음 활동과의 연결

3주차에는 기존 SMAA adaptation과 확보 소스를 항목별로 비교하고, SMAA 공간 처리를 보존하면서 적용할 부분을 설계한다. 원본 식을 보존할 reference, SMAA에 맞춘 변경, 필수 안전성 수정을 구분하고, 후보 선별·sampling·clipping·weight·feedback을 독립적으로 비교할 수 있는 구현 계획을 수립한다.

이번에 확인한 초기 history와 행렬 저장, 후보 목록 경계, resize 및 출력 연결 문제는 이후 구현·정확성 검증의 조건으로 넘긴다. 이번 주에는 알고리즘을 이식하거나 최종 8-case 측정을 시작하지 않았다.
